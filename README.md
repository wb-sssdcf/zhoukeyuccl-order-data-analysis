# 抽抽乐数据审核平台（小卡抽抽乐活动数据）

> 多管理员轮班共用 · 订单数据分析 + 碎卡兑换审核 + 宣传礼集赞兑换核对
> 在线地址：https://zhoukeyu-gacha-order-data-analysis.pages.dev/

为社群抽抽乐活动运营方开发的**浏览器端数据审核平台**：管理员上传微店/来豹接龙导出的订单，自动完成碎卡兑换审核与宣传礼集赞核对；多管理员**分班协作**，通过云端共享"碎卡审核记录 + 集赞礼兑记录"两套小表，修改全程留痕、可追溯。

## 核心能力

| 模块 | 说明 |
|---|---|
| 主订单分析 | 上传 Excel（6.8 万行级）本地解析：预览、卡型分布、销量 TOP、用户统计、活动期/满赠达标统计，不卡 UI |
| 碎卡兑换审核 | 按"提交"聚合审核兑换请求：通过 / 未找到用户 / 需人工处理；支持客服修改、人工放行，全程写修改历史 |
| 集赞礼兑核对 | 三 Sheet（审核通过/重复填问卷/审核不通过）导入核对，人工指定归属（微信昵称）、手动调整状态，自动重算并留痕 |
| 多管理员云端交接 | 云端只存两套小表（KV 快照），6.8 万行大表本地导入不上云；登录自动探测合并，支持暂不合并、稍后手动拉取 |
| 右下角悬浮窗 | 实时显示「当前登录账号｜数据来源账号｜同步状态」，并记录本页每次云端操作（可展开/收起），交接时一眼看清数据是谁的 |
| 修改留痕可追溯 | 页面内「📝 碎卡修改历史 / 📝 集赞修改历史」表 + Excel 导出的「修改与放行记录 / 集赞修改记录」Sheet，均含昵称列 |
| 一键导出 | 审核结果、未匹配清单、修改记录、来豹接龙查询表（含集赞修改记录）等均为纯本地生成，与云端无关 |

## 多管理员协作流程（v3 版本）

```
第 1 班（首次导入）：登录 → 上传主订单 → 上传碎卡表并审核 → 上传集赞表并核对 → 保存到云端
第 2 班起：登录 → 自动弹窗「云端发现上一班记录，是否合并？」→ 合并/暂不合并 →
          上传主订单 → 在已并入的记录上继续审核 → 保存到云端
```

- **上云（小表）**：碎卡审核提交记录（含修改历史、放行留痕）、集赞礼兑明细（含修改历史、处理状态）
- **不上云（大表）**：主订单 Excel，每次本地上传，避免突破 KV 存储上限
- **合并规则**：只增改、不删除本地；同一条两端都改过时，保留修改时间较晚的一方
- **保存保护**：导入文件不再自动保存云端；点「保存到云端」时会先拉取云端他人记录并入本地，再整份写回，降低并发覆盖风险
- **注意**：同一批次兑换表只允许第一个班导入一次；后续班次直接"合并云端 → 处理 → 保存"，不要重传碎卡/集赞文件，否则页面记录会被替换成原始未处理状态

## 界面与表格

- 提交级审核汇总表、兑换请求明细表均带 **✎已改** 列：该条被客服修改过或人工放行过即显示，悬停可看最近一次操作；集赞明细区同款标记
- 修改历史表（碎卡/集赞）与导出 Sheet 含**昵称列**，方便对账时识别是谁的记录

## 技术实现

| 项目 | 方案 |
|---|---|
| 前端 | 原生 HTML/CSS/JS 单文件（index.html，无框架） |
| Excel 解析 | SheetJS (xlsx@0.18.5)，兼容 UTF-8/GBK 编码 |
| 图表 | ECharts 5.4.3 |
| 云端小表 | Cloudflare Workers KV（登录鉴权 + 整份快照读/写） |
| 登录 | Workers 侧账号校验（ad001~ad004 + 运营方发放密码） |
| 部署 | GitHub 仓库 + Cloudflare Pages 自动部署 |

## 使用与部署

- 使用说明见仓库维护文档《抽抽乐网站使用说明》，含三上传区操作、修改历史查看位置、班次正确流程、常见问题排查表
- 部署：Cloudflare Pages 连接本仓库，构建命令留空、输出目录 `/`；登录与云端需配套部署 `functions/` 下的 Worker
- 本工具不上传订单主数据到任何服务器，Excel 均在浏览器本地解析
