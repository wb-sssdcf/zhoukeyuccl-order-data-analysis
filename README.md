# 订单数据分析平台

> 个人项目 | 3,400+ 下单用户 | 10万+ 订单 | 已上线

为社群运营方开发的**订单数据分析工具**。支持 Excel 批量导入、多维度统计、补邮状态管理、满赠达标自动判定。将原本数小时的手工统计缩短至分钟级，已被社群运营方实际采用。

## 🧠 项目回忆：怎么开始的

2026年7月13日，抽抽乐活动启动。运营方每天要从微店导出几百条订单 Excel，手工统计每个用户买了多少抽、有没有达到满赠门槛、该发什么赠品。

最头疼的是**补邮状态**——活动结束后需要给用户发补邮链接，但判断谁该补、谁已补、谁不需要补，全靠人肉一个个查。3000多用户，一次对账就是 3-4 小时。

我的抽卡记录器解决的是"用户端记录"问题，但运营方端的数据分析没人做。

7月20日，先写了一版 **Python 脚本**（`order_analysis.py`），用 pandas 把 Excel 吃进去，自动算出用户统计、卡片销量、满赠达标、活动时段分布。跑一次生成一份 Excel 报告。

但运营方不会用 Python。7月23日，重写为**网页版**——拖 Excel 进去，浏览器端跑完，直接看图表和表格。

**第一个 Web 版 → 迭代到第 10 版（7.23→8.2），两周内改了 20+ 次。**

## 功能模块

### 数据导入

| 功能 | 说明 |
|------|------|
| Excel/CSV 导入 | 支持微店/来豹接龙等平台导出的订单格式 |
| 数据校验 | 自动检测格式错误、重复订单，显示解析结果 |
| 分批加载 | 10万+ 条数据浏览器端处理，用 Web Worker 避免卡 UI |
| 数据归一化 | 兼容不同编码（UTF-8/GBK）、不同日期格式（`2026/7/11` `2026-07-11` `2026年7月11日`） |

### 五个分析视图

| 视图 | 功能 | 面试讲什么 |
|------|------|-----------|
| **全部数据** | 订单明细列表，支持筛选、搜索、分页，可导出 Excel | 10万条不卡爆浏览器的分页策略 |
| **用户统计** | 每人购买量、金额排名，消费行为分析，端盒统计 | 复杂业务规则的建模 |
| **卡片统计** | 每款卡牌销量、销售额排名，ECharts TOP15 图表 | 数据清洗——商品名称各种格式统一 |
| **活动期统计** | 按活动时段（0-1小时/1-6小时/6-24小时/浪漫疯）对比销售趋势 | 时间段判断逻辑 |
| **满赠达标** | 自动计算满赠门槛（10/20/30/.../120抽），筛选达标用户名单 | 多级满赠规则的引擎设计 |

### 高级功能

- **补邮状态管理**：三态自动判定——无需补邮 / 已补邮 / 未补邮，支持手动切换，导出报表
- **来豹接龙兼容导出**：导出格式可直接导入接龙工具（运营方实际工作流）
- **端盒打包计费**：活动有"381抽一盒"的打包规则，需要把订单拆开重新算抽数
- **多份装商品处理**：有些商品一次买 N 份，需要按份数拆分
- **海外手机号适配**：部分用户手机号是 +852/+886 开头，标准化处理

## 🔧 技术栈详解

| 层级 | 技术 | 为什么选它 |
|------|------|-----------|
| 前端框架 | 原生 HTML/CSS/JS | 和抽卡记录器一样——快速迭代不折腾 |
| Excel 解析 | SheetJS (xlsx@0.18.5) | 浏览器端读 Excel 的唯一成熟方案 |
| 图表 | ECharts 5.4.3 | 比 Chart.js 更适合数据量大的业务分析场景 |
| 存储 | localStorage | 缓存解析结果，刷新页面不丢 |
| 部署 | Cloudflare Pages | 同上 |
| 原始分析 | Python + pandas | 第一版用 Python 脚本验证数据分析逻辑 |

### 为什么从 Python 脚本演进到 Web 版

1. Python 脚本只能我一个人跑，运营方不会装 Python
2. 数据更新频繁（每天新订单），每次都要我手动跑脚本
3. Web 版放在 Cloudflare Pages，运营方自己打开网页拖 Excel 就行
4. Web 版加上了交互式筛选、搜索、导出，Python 脚本做不到

### 10万+ 数据浏览器端处理怎么不卡

| 策略 | 实现 |
|------|------|
| **分页渲染** | 表格每次只渲染当前页 50 条，不是 10万条全渲染 |
| **分批解析** | Excel 解析用 `sheet_to_json` 异步分片，不是一次性全读完 |
| **虚拟滚动** | 表格滚动时动态加载可见行 |
| **localStorage 缓存** | 解析结果存 localStorage，刷新页面不用重新上传 |
| **ECharts 按需渲染** | 图表初始隐藏的 tab 不渲染，切过去再画 |

## 🧪 踩过的坑（面试能聊）

### 1. 商品名格式地狱

微店导出的商品名千奇百怪：
- `周柯宇爱意正值炽夏小卡抽抽乐-R44`
- `「周柯宇 fully unlocked」爱意正值炽夏小卡抽抽乐-SR8`
- `爱意正值炽夏小卡抽抽乐-浪漫疯·比耶`
- `【补邮转链】「周柯宇 fully unlocked」爱意正值炽夏小卡抽抽乐.浪漫疯·看手机`

**解决**：写了一套清理规则链——去掉品牌前缀「周柯宇...」→ 去掉活动名 → 去掉括号 → 去掉末尾点号。Python 版用 `str.replace` 链，Web 版用正则。

### 2. CSV 编码乱码

微店导出的 CSV 有的是 UTF-8，有的是 GBK。SheetJS 读 GBK 的 CSV 直接乱码。

**解决**：上传时先用 `FileReader.readAsText()` 读原始文本，检测编码（BOM 标记），如果是 GBK 就转 UTF-8 再丢给 SheetJS。

### 3. 端盒打包计费

活动有 "381抽 = 1盒" 的打包规则。一个用户买了 500 抽，实际是 1 盒（381抽）+ 119 单抽。需要拆开计算抽数和金额。

**解决**：对每个用户的订单先做总抽数聚合，然后 `Math.floor(totalDraws / 381)` 算盒数，余数算单抽，金额用 `盒数 * 381 * 单价 + 余数 * 单价`。

### 4. 满赠规则多级嵌套

满赠有多个档位（10/20/30/40/50/66/88/100/120抽），不同档位送不同卡。还有"首次下单用户"和"非首次"的区别（浪漫疯活动）。

**解决**：用配置化方式定义满赠规则，用户维度的达标判定用 `for` 循环遍历规则配置表。每个用户跑一遍所有规则，返回该拿的赠品列表。

**这题面试能聊架构**：如果规则表配在 JSON 里而不是硬编码，运营方可以自己改规则不用改代码。

### 5. 补邮三态判断的边界情况

补邮状态：
- 需要补邮但还没补 → "未补邮"
- 已经补邮了 → "已补邮"  
- 不需要补邮（比如没买东西）→ "无需补邮"

边界情况：用户 A 在活动期买了，活动结束后又补了一次邮，怎么判断这次是"正常下单"还是"补邮"？

**解决**：通过订单描述关键词匹配——含"补邮""转链"关键词的标记为补邮订单。如果用户有补邮订单且补邮时间在原订单之后 → "已补邮"。

### 6. localStorage 5MB 上限

10万条订单解析完存 localStorage，JSON.stringify 后约 8MB，超了。

**解决**：只缓存解析后的统计数据（用户维度聚合），不存原始订单明细。统计数据大约 500KB。原始数据需要时重新上传 Excel。
