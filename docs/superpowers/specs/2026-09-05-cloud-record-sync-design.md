# 云端只同步审核记录（记录同步）设计文档

日期：2026-09-05
状态：已获用户批准，进入实施

## 背景

站点服务多客服轮班审核抽抽乐订单。主订单 Excel（来豹接龙导出）6.8 万行、约 15MB，不适合整表上云（Cloudflare KV 单值 25MB 上限，弱网上传必断）。经确认：

- 云端只同步「审核修改记录」：碎卡审核提交表、集赞礼兑表等来豹接龙导出表的各子表（量级几千行）。
- 6.8 万行订单底表不进云端，每个客服本地导入同一份 Excel。
- 接班流程：登录后自动拉取云端记录 → 与本地记录合并 → 继续审核；审核修改照旧自动保存到云端。

## 云端存储

- 沿用 Cloudflare KV，键 `gacha_data`，值为整份 JSON：
  ```
  {
    suika: [...],   // 碎卡审核提交记录
    jizan: [...],   // 集赞礼兑记录
    // 后续来豹接龙新增子表一律照此扩展
    updatedAt: <iso>,
    updatedBy: <account>
  }
  ```
- 不含 6.8 万行订单（rawOrders/users 等大表）。
- 上传即整份覆盖云端（last-write-wins + 409 冲突拦截，沿用现有实现）。
- 操作日志 gacha_log 继续保留（最近 200 条）。

## 合并规则（云端并入本地，只增改、不删除）

以"记录行唯一键"判同一条（碎卡取 phone+orderNo+code 组合等，各子表自定 key 函数）：

1. 云端有、本地无 → 新增到本地
2. 两边都有、内容一致 → 不动
3. 两边都有、内容不一致（冲突）→ 保留修改时间较晚的一条；摘要报冲突条数
4. 本地有、云端无 → 保留本地（绝不因合并删除本地行）

## 接班流程与弹窗

登录成功后自动执行，分 5 阶段：

| 阶段 | 内容 |
|---|---|
| 1 发现 | 检测到云端记录：各子表条数、更新于、更新账号 |
| 2 确认 | 弹窗：【开始合并】【暂不合并】（暂不合并则不动本地，可稍后手动拉取） |
| 3 合并中 | 进度提示：逐子表"正在比对碎卡记录…""正在比对集赞记录…""正在更新统计…" |
| 4 完成 | 摘要：新增 a 条、更新 b 条、冲突 c 条（冲突按较新者保留） |
| 5 兜底 | 提示"合并只增改、不删除本地记录；保险起见可先导出 Excel"，弹窗内提供导出入口 |

## 上传保存

- 审核中修改 → 防抖自动 PUT 云端（只含子表记录，几十 KB，秒传）。
- 409（云端已被他人更新）→ 弹窗提示，可选强制覆盖或取消后先拉取合并（沿用现有实现）。

## 页面改动范围

- index.html：cloudCollectSnapshot 改为收集各子表（不含 rawOrders/users 大表）；cloudApplySnapshot 改为上述合并逻辑；登录后自动拉取 + 阶段弹窗/进度 UI；原「保存到云端/从云端载入」按钮语义改为"保存我的记录 / 手动拉取记录"。
- functions/api/data.js：键内容随新快照结构，读写逻辑不变（GET/PUT + 409 + force + 日志）。

## 明确不做

- 云端删除同步（作废用状态标记，不物理删行）
- 6.8 万行订单上云
- 撤销合并（误操作影响小：只增改不删；用"先导出备份"兜底）
